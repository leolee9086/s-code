## 本轮完成：小红书/知乎搜索 + 持久状态 + 结果缓存

### 新增文件

1. **`src/search/engines/site-scoped.ts`** — 站点限定搜索引擎适配器
   - 通过 DuckDuckGo `site:` 语法搜索特定平台
   - 实现 `SearchEngine` 接口，无缝接入多引擎聚合系统
   - 使用与 DuckDuckGo 相同的 HTML POST 爬取策略
   - 结果标记为各自引擎名称（如 "xiaohongshu"），供聚合器去重合并
   - 无需额外 API key

2. **`src/search/cache.ts`** — 搜索结果缓存
   - 借鉴 SearXNG 的 ExpireCache 设计
   - 内存 LRU Map + TTL（默认 100 条目 / 60 秒过期）
   - 相同关键词的重复搜索直接返回缓存结果
   - 全局单例 `globalResultCache`

### 已修改文件

3. **`src/search/selector.ts`** — 新增引擎
   - 小红书 `makeSiteScopedEngine("xiaohongshu.com", "xiaohongshu", ...)` 默认启用
   - 知乎 `makeSiteScopedEngine("zhihu.com", "zhihu", ...)` 默认启用
   - 权重 0.8（低于通用引擎，作为补充）

4. **`src/search/executor.ts`** — 持久化引擎健康状态
   - 新增 `getGlobalState()` 返回模块级单例 `ExecutorState`
   - 新增 `resetGlobalState()` 供测试
   - 熔断器跨工具调用持久化（连续 3 次失败暂停 5 分钟）

5. **`src/tool/websearch.ts`** — 集成新功能
   - `callMultiEngine` 使用 `getGlobalState()` 替代 `new ExecutorState()`
   - 搜索前检查 `globalResultCache`，减少重复请求
   - 成功结果写入缓存
   - `engineNames` 从实际返回结果的引擎推导（`[...new Set(results.map(r => r.engine))]`）

6. **`src/search/index.ts`** — 导出 Cache 模块

### 架构改进
- 新增引擎无需修改核心流程：实现 `SearchEngine` 接口 → 注册到 `selectEngines` → 自动参与并发执行 + 聚合去重
- 引擎健康追踪现在真正有效（之前每次调用创建新状态，熔断器从未触发）
- 结果缓存减少重复 API 调用，提升响应速度

### 下一轮可能的方向
1. **搜索类型路由** — 根据 params.type（fast/deep）选择不同引擎组合
2. **Exa/Parallel 结构化解析** — 将 MCP 返回文本解析为 `SearchResult[]` 后接入多引擎系统
3. **InstanceState 集成** — 将 VQD 缓存和引擎状态放入 InstanceState 实现按目录生命周期管理
