为当前编码会话创建并维护一个结构化的任务列表。跟踪进度，组织多步骤工作，并向用户展示状态。

## 何时使用
主动使用：
- 任务需要 3 个或更多不同的步骤或操作（不仅仅是单个概念步骤的 3 次工具调用）
- 工作不简单且需要规划
- 用户提供多个任务（编号或用逗号分隔）或明确要求待办列表
- 新指令到达——将其捕获为待办项
- 开始一个任务时——标记为 `in_progress`（一次只能有一个）
- 完成一个任务时——标记为 `completed` 并添加工作中发现的后续事项

## 何时不使用
跳过：
- 工作是单个、直接的任务（或少于 3 个简单步骤）
- 请求纯属信息性或对话性质
- 跟踪不增加组织价值

## 状态
- `pending` - 未开始
- `in_progress` - 正在积极处理（一次只能有一个）
- `completed` - 成功完成
- `cancelled` - 不再需要

## 规则
- 实时更新状态；不要批量标记完成
- 仅在所需工作实际完成后才标记 `completed`，包括任何所需的验证。决不基于意图。
- 在有未完成工作的情况下，保持恰好一个 `in_progress`
- 如果受阻或不完整，保持 `in_progress` 状态并添加描述阻塞器的后续待办项
- 保留用户提供的命令的原始形式（标志、参数、顺序）
- 待办项应具体且可操作；将大工作分解为小步骤

## 示例

应该使用：
- "添加暗色模式切换并运行测试" -> 多步骤功能 + 显式验证
- "在仓库中重命名 getCwd -> getCurrentWorkingDirectory" -> grep 发现 8 个文件中的 15 处
- "实现注册、分类、购物车、结账" -> 多个复杂功能

跳过：
- "如何用 Python 打印 Hello World？" -> 信息性
- "为 calculateTotal 添加注释" -> 单个编辑
- "运行 npm install 并告诉我发生了什么" -> 一条命令

拿不定主意时，使用它。
