为当前编码会话创建并维护一个结构化的任务列表。
跟踪进度，组织多步骤工作，并向用户展示状态。

## 何时使用

任何难度，任何范围的任务都必须建立任务清单，否则你将无法调用任何编辑修改类工具。

使用注意事项：

- 开始一个任务时——标记为 `in_progress`
- 同一时间只能够有一个任务被标记为`in_progress`
- 完成一个任务时——标记为 `completed` 并添加工作中发现的后续事项
- 每一个任务都必须有明确的验证方式

## 何时不使用

- 仅限于极其简单的单轮问答时可以不调用

## 状态

每一个任务的状态可以为以下之一

- `pending` - 未开始
- `in_progress` - 正在积极处理（一次只能有一个）
- `completed` - 成功完成
- `cancelled` - 不再需要

## 规则

- 实时更新状态；不要批量标记完成
- 仅在所需工作实际完成并通过所有必要的校验之后才标记 `completed`。
- 在有未完成工作的情况下，保持恰好一个 `in_progress`
- 如果任务受阻或者需要前置步骤，保持`in_progress` 状态，并且添加需要前置完成的任务
- 保留用户提供的命令的原始形式（标志、参数、顺序）
- 待办项应具体且可操作；
- 如果整体目标较为宽泛，应该先跟用户讨论或者自行调研，将其分解为多个明确的执行步骤

## 示例

应该使用：
- "添加暗色模式切换并运行测试" -> 多步骤功能 + 显式验证
- "在仓库中重命名 getCwd -> getCurrentWorkingDirectory" -> grep 发现 8 个文件中的 15 处
- "实现注册、分类、购物车、结账" -> 多个复杂功能

跳过：
- "如何用 Python 打印 Hello World？" -> 信息性
- "为 calculateTotal 添加注释" -> 单个编辑
- "运行 npm install 并告诉我发生了什么" -> 一条命令

任何时候，如果你无法明确判断是否需要使用任务列表，你就应该使用它。
