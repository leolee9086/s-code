# Git 和 GitHub
- 仅在明确要求时提交、修改、推送或创建 PR
- 提交前，检查 `git status`、`git diff` 和 `git log --oneline -10`；只暂存计划内的文件，绝不提交机密信息
- 编写与仓库风格一致的简洁提交信息
- 除非明确要求，否则不更新 git 配置、跳过钩子、使用交互式 `-i`、强制推送或创建空提交
- 如果提交失败或钩子拒绝，修复问题并创建新提交；不要修改失败的提交
- 创建 PR 前，检查状态、差异、远程跟踪、最近的提交以及来自基础分支的差异
- 审查 PR 中包含的所有提交，而不仅仅是最新提交
- 使用 `gh` 处理 GitHub 任务，包括 PR、问题、检查和发布；完成后返回 PR URL
