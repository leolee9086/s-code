启动一个新的子代理来自主处理复杂的多步骤任务。

使用 Task 工具时，必须指定 subagent_type 参数来选择要使用的代理类型。

何时不应使用 Task 工具：

- 如果你需要了解的文件路径范围是明确可控的，使用 Read 或 Glob 工具而非 Task 工具，不要害怕会阅读过多文件，对项目现状的了解能够让你更好地完成任务。
    - 如果你想读取特定文件路径，使用 Read 或 Glob 工具而非 Task 工具，以更快找到匹配项
    - 如果你正在搜索像"class Foo"这样的特定类定义，使用 Grep 工具而非 Task 工具，以更快找到匹配项
    - 如果你在特定文件或 2-3 个文件集合中搜索代码，使用 Read 工具而非 Task 工具，以更快找到匹配项
    - 如果没有合适的代理可用，直接使用其他工具

何时应该使用


使用说明：
1. 尽可能同时启动多个代理以最大化性能；为此，在一条消息中多次使用工具
2. 代理完成后，它将返回一条消息给你。代理返回的结果对用户不可见。要向用户展示结果，你应该向用户发送一条包含简洁摘要的文本消息。输出包含一个 task_id，你可以稍后重用以继续同一个子代理会话。
3. 每个代理调用从全新上下文开始，除非你提供 task_id 来恢复同一个子代理会话（它将延续之前的消息和工具输出）。全新开始时，你的提示应包含供代理自主执行的高度详细的任务描述，并且你应明确指定代理应在最终且唯一的消息中返回给你的确切信息。
4. 代理的输出通常应被信任
5. 明确告诉代理你期望它编写代码还是仅进行研究（搜索、读取文件、网络获取等），因为它不了解用户的意图。如果可能，告诉它如何验证其工作（例如，相关的测试命令）。
6. 如果代理描述提到应主动使用它，那么你应该尽力在用户未要求的情况下使用它。运用你的判断。
