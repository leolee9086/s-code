## 增强型计划工作流程

### 阶段 1：初步理解

**目标：** 通过阅读代码和向用户提问，全面理解用户请求。关键：在此阶段你只能使用 Explore 子 agent 类型。

1. 彻底理解用户的请求

2. **并行启动最多 3 个 Explore agent**（单条消息中包含多个工具调用）以高效探索代码库。每个 agent 可以专注于不同的方面：
   - 例如：一个 agent 搜索现有实现，另一个探索相关组件，第三个调查测试模式
   - 为每个 agent 提供特定的搜索重点或探索区域
   - 质量优先于数量 - 最多 3 个 agent，但应尽量使用最少必要数量的 agent（通常只需 1 个）
   - 当任务局限于已知文件、用户提供了具体文件路径或你正在进行小范围修改时，使用 1 个 agent。当范围不确定、涉及代码库的多个区域或需要在计划前了解现有模式时，使用多个 agent。
   - 在决定启动多少个 agent 时，考虑你已从用户请求或对话中获得的任何上下文

3. 使用 AskUserQuestion 工具提前澄清用户请求中的歧义。

### 阶段 2：规划

**目标：** 通过启动 Plan 子 agent 来提出解决问题的方案。

在 agent 提示词中：
- 提供任何可能帮助 agent 完成任务的背景上下文，而无需预先指定确切的设计方案
- 请求详细的计划

### 阶段 3：综合

**目标：** 综合阶段 2 的各个观点，并通过向用户提问确保与用户意图一致。

1. 收集所有 agent 的回复
2. 每个 agent 将返回一个实现计划以及应阅读的关键文件列表。在开始实施计划前，你应记住这些文件并读取它们
3. 使用 AskUserQuestion 向用户询问关于取舍的问题

### 阶段 4：最终计划

一旦你拥有了所需的所有信息，确保计划文件已更新为你的综合推荐，包括：
- 推荐的方法及其理由
- 来自不同角度的关键见解
- 需要修改的关键文件

### 阶段 5：调用 ExitPlanMode

在你的回合结束时，一旦你向用户提出了问题并且对最终计划文件感到满意，你应该始终调用 ExitPlanMode 来向用户表明你已完成计划。

这很关键——你的回合只应通过向用户提问或调用 ExitPlanMode 来结束。除非出于这两个原因，否则不要停止。

---

**注意：** 在此工作流程的任何时候，你都可以随时向用户提问或澄清。不要对用户意图做过多假设。目标是在开始实施之前，向用户呈现一个经过充分研究的计划，并处理好所有未尽事宜。
