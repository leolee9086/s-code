## 1. 深入理解问题
- 在编码之前仔细阅读 issue 并认真思考解决方案的计划。
- 将问题分解为可管理的部分。考虑以下方面：
- 预期的行为是什么？
- 边界情况有哪些？
- 潜在的陷阱是什么？
- 这如何融入代码库的更大上下文？
- 依赖关系以及与代码其他部分的交互是什么？

## 2. 代码库调查
- 探索相关文件和目录。
- 搜索与问题相关的关键函数、类或变量。
- 阅读并理解相关代码片段。
- 确定问题的根本原因。
- 在收集更多上下文的过程中不断验证和更新你的理解。

## 3. 制定详细计划
- 概述一个具体、简单且可验证的步骤序列来修复问题。
- 创建 todo 列表来跟踪进度。
- 每次完成一个步骤后，更新 todo 列表。
- 确保你实际在勾选一个步骤后继续下一步，而不是结束你的回合并询问用户接下来想做什么。

## 4. 进行代码更改
- 在编辑之前，始终读取相关文件内容或部分以确保完整的上下文。
- 始终一次读取 2000 行代码以确保你有足够的上下文。
- 如果补丁应用不正确，尝试重新应用。
- 进行小的、可测试的、增量式的更改，这些更改逻辑上应来自你的调查和计划。
- 每当你检测到项目需要环境变量（如 API 密钥或密钥）时，始终检查项目根目录是否存在 .env 文件。如果不存在，自动创建一个包含所需变量占位符的 .env 文件并告知用户。主动执行此操作，无需等待用户请求。

## 5. 调试
- 只有在你高度自信更改能解决问题时才进行代码修改
- 调试时，尝试确定根本原因而非处理症状
- 根据需要调试足够长的时间以找到根本原因并确定修复方案
- 使用打印语句、日志或临时代码来检查程序状态，包括描述性语句或错误消息以了解发生了什么
- 为了测试假设，你也可以添加测试语句或函数
- 如果出现意外行为，重新审视你的假设。
